# 工作台多 Agent 协作改造方案（2026-08-24 完整版，待审核）

> 范围：在 DeepSeek Harness Desktop 工作台里，把"多代理协作"从 AI 协作面板的重操作，升级为普通对话里可用的第一等能力；同时保留并强化现有 AI 协作整页。
> 本方案基于：行业调研（Anthropic / OpenAI / Claude Code / Devin / Cursor / Jules / Magentic-One / CrewAI / Manus / GitHub Copilot / LangChain / LukeW UI 研究）+ 官方 DeepSeek Harness RC.7/RC.8 新能力 + 工作台现状（单/多 AI 切换、AI 编排、知识库）。

---

## 一、调研结论：成熟方案怎么做多 Agent 协作

### 1. 实现模式（引擎层）

| 模式 | 代表 | 要点 |
|---|---|---|
| 编排者-工作者（orchestrator-worker） | Anthropic Research、Magentic-One、LangChain Subagents | 一个主代理负责规划/拆解/汇总，多个子代理并行执行独立子任务；主代理"把子代理当工具调用" |
| 任务账本 + 进度账本 | Magentic-One | 主代理维护结构化任务清单与进度自省（"是否卡住"），跨轮次存活 |
| 同步 vs 异步（后台） | Claude Code `run_in_background`、Codex 后台线程、LangChain async job | 同步=主代理等结果；异步=返回 job id，可继续对话，完成通知 |
| 依赖拓扑 | Claude Code Task `blockedBy/blocks`、工作台现有 `dependsOn` | 有依赖的串行、无依赖的并行，防止竞态 |
| 上下文隔离 | Anthropic（子代理独立上下文+精简返回）、LangChain（子代理无状态） | 子代理各自干净上下文，只回最终文本/摘要，防止主线程膨胀 |
| 工件落盘 | Anthropic artifact 模式 | 子代理把代码/报告写入文件，只传回引用，避免"传话游戏"信息失真 |
| 隔离执行环境 | Claude Code/Cursor（git worktree）、Devin（独立 VM）、Jules（云 VM） | 并行写操作互不冲突；实验性改动可整体丢弃 |
| 产品子代理 | DeepSeek Harness RC.8（Codex/Claude Code Bundle）、Claude Code 团队模式 | 把另一个成熟产品进程当子代理，黑盒执行，只回最终文本 |
| 规模规则 | Anthropic（提示词嵌入投入预算） | 简单任务 1 个子代理少量工具，中等 2-4 个，复杂更多；防止过度投入 |

### 2. 使用模式（用户怎么操作）

- **主线程是指挥中心**：用户在正常对话里发任务，子代理在后台/侧栏工作（Codex/ChatGPT、Claude Code）。
- **方案先行 + 人工确认**：Copilot/Manus/Cursor 都先出计划再动手；工作台现有 AI 协作页就是这个模式，用户认可，应保留。
- **中途可干预**：Devin 可给子会话发消息/暂停/终止；Claude Code 可 promote/kill 后台代理；Codex 审批浮层可跳转到来源线程。
- **结果以工件/链接呈现**：Manus 交付物卡片、Devin 子会话链接、Copilot PR 链接。

### 3. 展示模式（UI 怎么呈现）

| 来源 | 模式 |
|---|---|
| LukeW（Bench/ChatDB/Intent） | 渐进披露：默认一行摘要可展开；"工作即进度条"；左列过程/右列结果，完成后左列折叠成摘要 |
| Codex TUI / ChatGPT | 子代理侧栏：左列全部代理实时状态，右列选中代理输出；Active/Done 列表；审批浮层显示来源线程可跳转 |
| Manus | 左侧任务计划 pending→in_progress→completed 实时勾选；右侧虚拟机过程；完成项绿色删除线 |
| GitHub Copilot / Devin | 集中式任务面板/Mission Control：启动、跟踪进度、查看结果、引导进行中会话 |
| CrewAI / Cursor | 画布/侧栏集中管理多个代理；每步一张卡（任务+执行代理合一）；可并行跑多个方案对比 |
| 反方（LukeW 两派之争、Cognition "Don't Build Multi-Agents"） | 一部分人觉得过程刷屏，一部分人需要可监控；结论是**默认折叠、按需展开、可关闭**；多代理仅在高价值/可并行/延迟敏感任务上值得（token 约 15 倍于聊天） |

### 4. 对工作台的启示（设计原则）

1. **单代理是默认，多代理是按需**：简单任务直发；只有可并行/高价值/复杂任务才进多代理，避免过度工程和 token 浪费。
2. **主线程=对话，子代理=可展开的卡片**：默认一行状态，点击展开详情；过程不刷屏。
3. **方案先行 + 确认**：保留 AI 协作整页；对话流卡片与详情抽屉只是更快入口。
4. **双轨子代理并存**：轨道 A（in-process，可审计、状态/日志/重试完整、可分配模型）与轨道 B（Codex/Claude Code 产品子代理，黑盒、借力成熟产品）任务类型不同，都保留。
5. **人工关口明确**：只读/检索可自动并行；写操作默认确认；审批浮层可跳转来源。
6. **并行正确性与成本护栏**：依赖拓扑 + 并发上限 + token 预估 + 停止/恢复 + 官方 reportDelivery 唤醒。
7. **隔离**：写型子代理可选 git worktree，避免并行写冲突。

## 三、架构总览

```
普通对话（主线程 = 指挥中心）
  ├─ 复杂度/价值评估（G3 路由）
  │    ├─ 简单 → 直发主代理（单代理）
  │    ├─ 中等/复杂且可并行 → 轨道 A：harness in-process 子代理编排
  │    │        ├─ 拆解 → 依赖拓扑 → 并行执行（maxParallel，≤4 可调）
  │    │        ├─ reportDelivery 完成即唤醒主代理
  │    │        └─ 状态经 Job Panel / 对话流卡片 / 详情抽屉展示
  │    └─ 特定任务（如借力成熟产品） → 轨道 B：Codex / Claude Code Bundle 子代理（按需，黑盒）
  └─ 交互入口
       ├─ 对话流并行卡片（默认折叠，可展开）
       ├─ 详情抽屉（右侧滑出：方案/代理/日志/记忆/决策）
       ├─ AI 协作整页（保留：整体看方案→确认→验收）
       ├─ 审批浮层（写操作，可跳转来源子代理）
       └─ Job Panel / 后台任务面板（统一管理：进行中/完成/失败/kill/promote）
```

## 四、阶段计划

### 阶段 E：会话内并行骨架（对话流 + 开关语义化）

| 项 | 内容 | 完成条件 |
|---|---|---|
| E1 | 单/多 AI 开关语义化：单 AI = 直发原生会话（不再建编排任务）；多 AI = 允许并行子代理；复杂度自动判断保留，但快速问答不再产生编排记录 | 简单问答延迟不劣化、零编排记录；单 AI 下复杂问题也能直发主代理 |
| E2 | 对话流并行卡片：多 AI 发送后出现一行状态卡（"3 个子代理并行中 · 2/3 完成"），点击展开子代理列表（名称/状态/模型/耗时/失败原因），完成后折叠为主代理汇总卡；卡片带"查看完整记录"入口 | 一次复杂任务全程不离开对话流可完成并修订；卡片默认折叠不刷屏 |
| E3 | 写操作确认门：并行子代理只做只读/检索/分析；写文件、执行命令前在卡片内出确认，审批浮层显示来源子代理并可跳转（借鉴 Codex approval overlay） | 写操作默认确认；只读自动并行不受影响 |
| E4 | 详情抽屉（实验）：从对话流卡片点开右侧抽屉，Tab=方案/代理状态/日志/记忆/决策，复用现有编排面板数据；**保留 AI 协作整页不动** | 抽屉可打开/返回；AI 协作页功能无回归；效果不好可回退 |
| E5 | 成本与并发护栏：并行上限默认 3（可调 ≤4）；卡片显示预计/实际 LLM 调用与 token 量级；运行中可停止，停止后可恢复未完成部分 | 冒烟覆盖上限/停止/恢复；成本信息在概览可见 |

### 阶段 F：双轨子代理引擎

| 项 | 内容 | 完成条件 |
|---|---|---|
| F1 | 轨道 A 完善：现有 in-process 编排升级为异步收集 + reportDelivery"完成即唤醒父任务"（不等整批）；依赖拓扑保留；模型分配保留 | 长时间任务首条结果到达显著早于整批；乱序/唤醒有 E2E 证据 |
| F2 | 轨道 B 接入：Codex/Claude Code Bundle 按需安装（UI 引导，装前备份 profile 三件套）；未装时明确提示安装路径；权限模式只读起步（Codex `never` / Claude `dontAsk`）；Codex 多命名实例可选 | 同一编排可选择轨道 A/B；B 未装时 UI 给出安装引导；B 只回最终文本，过程黑盒 |
| F3 | 后台任务统一管理：工作台编排任务在官方 Job Panel 可见（进行中/完成/失败/kill/恢复），与任务库双向 | 官方 Job Panel 能查到工作台发起的子代理任务 |
| F4 | web_search 并发：知识检索 webFallback 多问题并发查询 | trace 有并行重叠证据 |
| F5 | 多模态链路验证：/goal、/plan 图文输入在工作台可用（模型需支持） | 截图/图片可进任务并被引用 |
| F6 | 隔离选项：写型子代理可选 git worktree（默认关），避免并行写冲突；实验性改动可整体丢弃 | 开启时并行写互不冲突；关闭时行为不变 |

### 阶段 G：自动并行与智能分流

| 项 | 内容 | 完成条件 |
|---|---|---|
| G1 | 只读/检索类自动并行（默认开）：普通消息含多个可拆解的只读子问题时，主代理自动并行拆给子代理，卡片显示"已并行 N 个子代理" | 只读自动并行默认开、可一键关；"同时查 N 件事"类提问有并行证据 |
| G2 | 写操作建议卡（默认确认）：检测到写操作时出"建议并行"卡片，确认后才执行 | 写操作不默认自动并行；确认卡冒烟覆盖 |
| G3 | 智能分流（借鉴 Anthropic 规模规则）：简单→单代理；中等→2-4 个轨道 A 子代理；复杂/可并行→更多；特定任务类型（成熟产品擅长）→轨道 B；把"是否值得多代理"（价值×可并行度×延迟收益）编入主代理提示 | 分流规则有评测集；简单任务不会误进多代理 |
| G4 | 数据驱动调优：观察 1-2 周真实使用（拒绝率/修改率/token/延迟），调整阈值与默认策略 | 有真实数据；默认策略据此收敛 |

### 阶段 H：回归与收尾

| 项 | 内容 | 完成条件 |
|---|---|---|
| H1 | 并行正确性专项：并发上限、乱序、失败重试、唤醒及时性、停止/恢复、双轨混跑 | 全量 smoke + 专项 E2E 通过 |
| H2 | 官方升级兼容：SQLite 迁移备份、Job Panel、Bundle 实测 | 升级前后数据完好；官方能力实测通过 |
| H3 | 部署 + SHA-256 + 日志补录 + 大阶段蒸馏 | 与安装目录哈希一致；C 编号连续；蒸馏按大阶段策略 |

### 依赖顺序

```
E1 → E2 → E3 → E4 → E5
        ↓
      F1（轨道A异步+唤醒）→ F3（Job Panel）→ F4/F5/F6
        ↓
      F2（轨道B按需，可并行推进）
        ↓
      G1/G2 → G3 → G4 → H1-H3
```

### 实施状态（2026-08-24，用户已按推荐确认 5 个决策点）

- **E1 已实施**：多 AI 模式下快速问答（自动判断为低复杂度）改为 `session.prompt()` 直发原生会话，零编排记录；单 AI 保持原生直发；"始终编排"策略仍走完整编排。
- **E2 已实施**：对话流新增并行状态卡片（默认一行摘要：`⏳ N 个子代理并行中 · M/N 完成 · 已用时间`，点击展开子代理列表：名称/状态/模型/耗时/失败原因），完成后自动折叠，主代理汇总卡保留"详情抽屉/任务中心"入口。
- **E3 已实施**：host 端子代理默认 `readOnly=true`（workerPrompt 注入只读约束）；方案含写操作子代理（`readOnly:false`）时，自动启动前出"写操作确认卡"（仅读执行 / 允许写操作）；客户端增加审批浮层（监听会话 pending approval，允许一次/拒绝，最佳努力，官方审批 UI 仍可用）；方案生成提示词已声明 readOnly 规则（C0032 修复写门无法触发）。
- **E4 已实施**：对话流卡片新增"详情抽屉"（右侧滑出，Tab：方案/代理状态/日志/记忆/决策，复用现有编排数据），AI 协作整页保留不动。
- **E5 已实施**：并行上限默认 3（host 已 clamp 1-4）；卡片显示预计 LLM 调用次数与预估 token 量级；运行中可停止（orchestration_cancel）、失败/终止后可继续执行（orchestration_resume，只重跑未完成子代理）。
- **模型分配三档（2026-08-24 补充）**：全自动（balanced/quality/economy）/ 主代理手动·子代理自动（main-manual）/ 全部手动（manual）；对话流输入区新增"模型:全自动/主手动/全手动"循环按钮，AI 协作页策略下拉同步加"主代理手动"档，生成方案后仍可逐个调整。
- **失败恢复（2026-08-24 补充）**：子代理失败后自动换健康模型重跑（最多 2 次，优先同 provider，避开近期失败模型）；对话流卡片/工具栏协作页/详情抽屉均可对失败子代理单独"重试此子代理"（复用已完成子代理，只重跑失败者+主代理汇总）；子代理默认超时从 15 分钟下调到 10 分钟，降低"卡住感"；卡片操作行常驻显示"停止/继续执行"，随时可整体终止。
- 待办：应用重启后由用户实测 E1-E5；实测通过后进入 F 阶段（F1 轨道 A 异步+reportDelivery 唤醒 → F3 Job Panel → F2 轨道 B 试点）。

## 五、展示规格（UX 详细）

### 对话流并行卡片（E2 核心）

- 默认形态：一行，`⏳ 3 个子代理并行中 · 2/3 完成 · 已用 42s`，点击展开。
- 展开后：子代理列表，每行=头像/序号 + 名称 + 状态（等待/运行/完成/失败/重试中）+ 模型 + 耗时 + 失败原因；支持单条"重试/查看"。
- 完成后自动折叠成主代理汇总卡：最终报告 + 模型 + 耗时 + "查看完整记录"（打开详情抽屉）+"继续与主代理对话"。
- 视觉规范：沿用现有 `wb-collab-*` 样式；完成=绿色，失败=红，运行=脉冲蓝；不做动画刷屏。

### 详情抽屉（E4，实验）

- 右侧滑出（宽 420-520），Tab：方案（执行顺序/验收清单）/ 代理状态 / 日志（级别过滤+搜索）/ 记忆 / 决策（模型策略/反馈）。
- 数据源 = 现有编排记录，不新建存储；对话流卡片与 AI 协作页共享同一份数据。
- 支持在抽屉内直接"通过验收/要求修改/继续执行"（与 AI 协作页一致）。

### 审批浮层（E3）

- 子代理要写操作/执行命令时，顶部浮层：`子代理"代码审查"请求执行：npm run build` + [查看该子代理] [允许] [拒绝]。
- 借鉴 Codex：浮层显示来源子代理名，可先跳转到该子代理卡片再看上下文再决定。

### 后台任务面板（F3）

- 复用官方 Job Panel + 工作台导航红点：进行中/完成/失败数量；点击进任务中心 AI 协作页；支持 kill / 恢复。

## 六、风险与回退

| 风险 | 应对 |
|---|---|
| token 成本上升（多代理 ≈ 15 倍聊天） | E5 成本护栏 + G3 分流 + 只读自动并行可关 |
| 并行写冲突 | E3 写操作确认 + F6 worktree 隔离（默认关） |
| 过程刷屏 / 用户两派之争 | E2 默认折叠 + 可全局关闭子代理过程展示 |
| 轨道 B 黑盒/凭据/版本漂移 | F2 只读起步 + 装前备份 + 未装引导；先不装，等 E 主链路跑通 |
| 官方 rc 线 API 变动（0.1.1-rc.2 为 prerelease） | 阶段 F 全部以安装包实测为准；升级前备份 harness-home |
| 详情抽屉效果不好 | E4 为实验项，随时可回退，AI 协作整页不受影响 |
