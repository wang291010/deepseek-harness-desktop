## 阶段 E-H：多代理并行与对话化改造（2026-08-24 重规划）

> 触发：DeepSeek Harness 官方 RC.7/RC.8 更新推出子代理并行生态；工作台此前已具备"单 AI / 多 AI 切换"（P2.6）与"多AI协作编排"（P2.5），但两者割裂：并行子代理藏在"AI 协作"面板里，普通对话默认单 AI，主代理查看/修订要跳面板。
> 目标：把"子代理并行"变成普通对话的第一等能力——单/多 AI 开关即"是否允许并行子代理"的语义开关；AI 协作面板降级为详情抽屉；写操作保持人工确认，只读/检索类可自动并行。

### 官方更新依据（已核实）

- **RC.7（2026-08-17）**：Codex / Claude Code 子代理任务接入 Job Panel 统一管理。
- **RC.8（2026-08-19，共 14 项，与本改造相关）**：
  - 子代理收编：Claude Code、Codex 可作为 Profile Bundle 按需安装，在 Harness 工作流里充当具体任务执行者；
  - Codex 新增非交互权限模式 + 多个命名实例：一个任务可同时挂多个 Codex 干不同活（多实例并行）；
  - reportDelivery 机制：子代理结果及时回传并唤醒等待中的父任务，修正报告与任务结算通知乱序；
  - web_search 支持并发查询；
  - 多模态：/goal、/plan 支持图文混合输入；@ 菜单支持引用文件与历史会话（官方硬上限 3 个）；
  - Windows PTY 持久 PowerShell；SQLite 读写/分叉性能优化（数据结构不兼容，升级前需备份）。

### 版本基线（2026-08-24 核实）

- 应用内嵌核心 harness = `@deepseek-ai/dsh` 及全部核心包 **0.1.1-rc.2**（2026-08-23 更新安装，npm latest/next 同指此版本）。
- "rc.8"是 GitHub 开源仓库的发布标签 `v0.1.0-rc.8`（2026-08-19），与 npm 包版本线（0.1.1-rc.2）不是同一套编号；0.1.1-rc.2 是更晚的 npm 线，包含 rc.8 时代能力（Job Panel、reportDelivery、web_search 并发、多模态、子代理 bundle 支持），**核心不落后**。
- 注意：全局 `dsh` CLI（npm）仍是 0.1.0-rc.6（旧），管理 desktop profile 时应使用 `npx @deepseek-ai/dsh@0.1.1-rc.2` 或应用内嵌 CLI，避免用旧 CLI 改新 profile。
- 官方提示 SQLite 存储格式不兼容：升级/动 profile 前备份 `harness-home`。
- 阶段 F 的"官方新能力"一律以安装包实际能力验证为准，不照搬媒体对 rc.8 的描述。

### 工作台现状（与官方能力对照）

| 能力 | 工作台现状 | 与官方更新差距 |
