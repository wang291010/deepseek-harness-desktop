# 风格系统：问题记录与 V2 升级方案（2026-08-20）

> 状态：**方案已确认（决策点见 §六），未开始改代码**。本文档先记录用户反馈的 Bug 与需求，
> 并给出完整方案与实施路线；经确认后再按项目惯例（备份 → 实施 → 回归 → 文档 → 提交）执行。

## 一、摘要

1. **Bug 1**：调风格调到一半，设置突然全部恢复默认；页面没有保存按钮，用户不知道是自己
   触发了重置还是系统重置的。代码里确实存在"一键恢复默认"入口，且**无确认、无撤销、无历史**，
   同时自动保存机制在特定时序下会丢失改动或回滚旧快照。
2. **Bug 2**：毛玻璃、暗色遮罩等参数调整后没有任何效果。根因是：这些参数只在"已设置壁纸"
   且**命中几个硬编码的框架类名**时才生效，聊天主界面大概率没有命中；暗色遮罩只是一个压在
   壁纸层下的伪元素，界面本身不透光时永远看不到。
3. **需求 1**：风格页要做得更全面、可调参数更多、更个性化。
4. **需求 2**：学习市面风格插件（含 Wallpaper Engine 动态壁纸支持），做一套更丰富、更完整、
   可分享的风格系统。
5. **需求 3（预留，后续立项）**：DIY 自由度拉满——希望可以改到"按钮风格"这一层级，做到
   组件级定制；当前先不实施，不影响 M1–M4 执行，初步方案见 §4.9。

建议分四个里程碑推进：先修两个 Bug（含保存/撤销/历史机制），再做参数与主题包体系，再做
Wallpaper Engine 动态壁纸，最后做本地导入导出与打磨。决策点已确认，见 §六。

## 二、Bug 记录与根因分析

### Bug 1：调风格中途全部恢复默认 + 没有保存按钮

**用户现象**：正在调风格，调到一半突然全部恢复默认；页面上没有"保存"按钮，也不知道为什么
会自己重置。

**代码事实（只读核查，未改动）**：

- 风格页当前**没有显式保存按钮**，采用的是"改动后 450ms 防抖自动保存"（[client.js](C:/YourWorkbench/plugins/workbench/lib/client.js) 约 3295–3315 行）。
- 页面上唯一的"恢复默认"按钮（约 3336 行）会**直接**把全部设置替换为默认值并立即自动保存，
  **没有二次确认、没有撤销、没有历史记录**。
- 内置预设（专注/工作室/深夜）的"应用"按钮也是**整套覆盖**当前设置并立即保存，同样无确认。
- 选择壁纸是异步流程（约 3339–3346 行），期间如果用户继续调其它参数，图片处理完回来后会用
  **旧的设置快照**覆盖最新改动——表现为"改了半天突然跳回去了"。
- 每次读取风格文档时，`theme` 字段会被**强制覆盖**成主题服务的当前偏好（约 1387–1391 行），
  重启后用户选择的深色可能显示成"跟随系统"，看起来像被重置。
- 存储文件不存在时，服务端会**静默返回默认值**（[host/index.js](C:/YourWorkbench/plugins/workbench/lib/host/index.js) 约 288–299 行），页面不会报错——升级、清理、迁移后设置可能无声消失。
- 写入是"后写覆盖先写"（last-write-wins），**没有版本冲突检测**，也没有审计日志，出问题无法回溯。

**根因排序（按可能性）**：

| # | 根因 | 证据 | 表现 |
|---|---|---|---|
| A | "恢复默认"或预设"应用"被误触/误点，且无确认与撤销 | 唯一会"全部重置"的入口，一次点击即生效 | 全部变默认 |
| B | 壁纸异步回滚旧快照 | 选图处理期间继续调参会被旧 doc 覆盖 | 部分设置跳回旧值 |
| C | 页面重挂载 + 自动保存未落盘 | 切换页面/主题变化触发重载，450ms 防抖内改动丢失 | 最后几步改动丢失 |
| D | theme 被当前偏好强制覆盖 | 读取时 `theme: currentTheme` | 主题看起来被重置 |
| E | 存储文件缺失/被清理，服务端静默返回默认 | readStyleStore 对 ENOENT 静默降级 | 重启后全部默认 |

> 由于当前没有审计日志，无法从数据侧确认具体是哪一条触发；方案会先补上"版本号 + 历史快照 +
> 操作日志"，让同类问题以后可自查。

**修复方向（列入 P0，本次不动手）**：

1. 新增显式"保存/放弃更改"交互 + 未保存离开提示；自动保存保留但可关闭。
2. "恢复默认"与"应用预设"加二次确认，并提供**撤销**与**历史版本回滚**。
3. 壁纸选图改为基于最新状态的功能式更新，杜绝旧快照回滚。
4. 读取时以存储的 theme 为准，不再被当前主题服务偏好覆盖。
5. 写入加 revision 乐观锁（冲突时提示"已被其它窗口修改"并给出合并/覆盖选择）。
6. 每次保存前自动快照到历史（保留最近 N 份），支持一键找回。

### Bug 2：毛玻璃 / 暗色遮罩调参数没效果

**用户现象**：调整"毛玻璃""暗色遮罩"（以及界面不透明度）后，界面一点变化都没有。

**代码事实（只读核查，未改动）**：

- 毛玻璃与半透明效果只在 `body.wb-has-wallpaper`（**已设置壁纸**）时才生效（[client.js](C:/YourWorkbench/plugins/workbench/lib/client.js) 约 692–693 行）。
  **没有壁纸时，调这三个滑块从原理上就不会有任何可见变化。**
- 生效范围只覆盖 `.wb-nav`（左侧导航）、`.wb-page`（工作台页面）和两个**硬编码的哈希类名**
  `pI_x6G_frame` / `pI_x6G_sidebarCol`。哈希类名是编译产物，当前安装的主题包里搜索不到，
  **聊天主界面大概率没有命中**——所以即使设了壁纸，毛玻璃也盖不住聊天区域。
- 暗色遮罩是一个 `z-index:-1` 的伪元素，只压在壁纸图层上；聊天区、卡片等界面元素都是不透明
  背景，遮罩永远显示不出来。
- 右侧预览卡只对缩略图做了暗色遮罩，**没有真正应用毛玻璃**，所以滑块在预览里也看不出模糊。

**修复方向（列入 P0）**：

1. 重做背景渲染层：壁纸层 → 遮罩层 → 界面层分层，界面容器改用稳定的 class/data 属性定位，
   不再依赖哈希类名；确保聊天主界面、侧栏、设置面板全部纳入毛玻璃范围。
2. 无壁纸时也提供可见氛围效果（纯色渐变背景 + 背景模糊/遮罩仍生效）。
3. 预览卡真实应用毛玻璃/遮罩/不透明度，所见即所得。

## 三、市面同类插件调研（参考学习）

社区已出现多款 DeepSeek Harness 风格插件，核心能力与可借鉴点如下：

| 插件/项目 | 亮点 | 可借鉴点 |
|---|---|---|
| dsh-skin（KinGao294） | 多套 `--dsw-alias-*` 精选配色 + 半透明壁纸/遮罩/模糊；13 个颜色角色取色器 | 完整 token 换肤、已保存微调不被预设覆盖 |
| HeiGeAi skin | 21 套内置皮肤；**传一张图自动生成整套配色** | 图片生成主题包 |
| dsh-ui-appearance | 自由调色板、壁纸/视频背景（上传或 URL）、毛玻璃与半透明、背景氛围三滑块 | 壁纸/视频背景、面板与背景分离的透明度体系 |
| dsh-dream-skin | 8 套主题、主题包可分享、壁纸 2.0（URL/渐变/每皮肤建议/自动弱化） | 可分享主题包格式 |
| dsh-lluser-ui | 壁纸轮换、视频背景（mp4/m3u8 直链） | 轮换与流媒体背景 |
| dsh-theme-kit | 32 款配色主题、动态与静态壁纸、纸纹、分区透明度、文字深浅 | 分区透明度、纹理 |
| dsh-wallpaper-engine | 读取 Wallpaper Engine 目录，缩略图网格点选 Video/Web 壁纸内嵌；Scene/Application 自动剔除 | WE 集成做法 |
| dsh-market / dsh-skin 市场 | 主题一键安装、立即切换、重启保持 | 主题包市场与持久化 |

**共性最佳实践**：

1. 直接操作 DSH 主题 token（`--dsw-alias-*`）做整体系换肤，而不是只改几个变量。
2. 壁纸支持上传 / URL / 渐变 / 轮换 / 视频；**所有设置实时预览、自动持久化、重启保持**。
3. 半透明分三组独立滑块：面板不透明度、背景不透明度、背景模糊、背景遮罩。
4. 预设/主题包可保存、分享、导入导出，一键切换且互不干扰。

**Wallpaper Engine 技术边界**（来自 WE 官方文档与社区实现）：

- WE 壁纸在 `Steam/steamapps/workshop/content/431960/<壁纸ID>/` 目录下，含 `project.json`、
  `preview.jpg`，场景壁纸另有 `scene.json`，网页壁纸是 `index.html`，视频壁纸是 mp4/webm。
- **只有 Video 和 Web 壁纸可以内嵌到网页里**；Scene/Application 壁纸有独立渲染器，无法内嵌，
  社区插件的通用做法是从候选和选择器中剔除（或仅展示静态预览帧）。
- Web 壁纸在 DSH 内应放在**沙箱 iframe** 中渲染，并禁止其访问宿主网络与本地文件。

## 四、V2 风格系统方案

### 4.1 设计目标

1. **稳定**：改风格不再怕丢失、怕误触，任何操作可撤销、可回滚、可追溯。
2. **完整**：从"几个滑块"升级为"主题包 = 配色 + 壁纸 + 排版 + 氛围 + 对话风格"的完整体系。
3. **个性化**：DIY 参数大幅扩展，支持导入导出与分享，支持图片生成主题。
4. **沉浸**：壁纸（静态/视频/WE 动态）、毛玻璃、暗色遮罩真正作用于全界面，所见即所得。

### 4.2 总体架构（三层）

```
主题包（可分享、可导入导出）
  ├─ 配色：完整 token 集（亮/暗各一套）+ 强调色规则
  ├─ 壁纸：类型（无/图片/URL/渐变/视频/WE 壁纸）+ 显示模式 + 轮换
  ├─ 排版：字号/行高/圆角/间距/密度
  ├─ 氛围：背景不透明度/背景模糊/背景遮罩/光晕
  └─ 对话风格：默认表达 + 可覆盖提示词
        │
        ▼
全局自定义覆盖（用户在当前主题包上做的微调，保存后不丢）
        │
        ▼
渲染层（重做）：背景层 → 遮罩层 → 界面层（覆盖真实容器，不再依赖哈希类名）
```

### 4.3 数据模型 v2

存储文件升级为 schema v2（旧文件自动迁移、不删除）：

- `schemaVersion`、`activeThemeId`、`themePack`（当前生效的完整主题包）
- `overrides`（用户微调，独立于主题包，换主题后可保留）
- `wallpaper`（`{ type, source, fit, position, blur, mask, rotation[], videoOptions }`）
- `history[]`（最近 20 份快照，含时间与来源：手动保存/自动保存/应用预设/恢复默认）
- `audit[]`（最近操作日志：谁在何时做了什么，用于自查"为什么变了"）
- `revision`（乐观锁，防多窗口互相覆盖）
- `sessionStyles`（保留现有按会话对话风格）

### 4.4 P0：修复两个 Bug（先做，独立小步）

1. **保存机制重做**
   - 顶部状态区新增"保存""撤销""历史"按钮；自动保存默认开启，可在设置里关闭。
   - 有未保存改动时，切换页面/关闭窗口给出提示；写入失败明确弹错并支持重试。
   - 写入带 revision 乐观锁；冲突时提示并提供"保留我的/采用对方的/另存一份"。
2. **恢复默认与预设应用安全化**
   - "恢复默认"二次确认；应用预设保留"撤销本次应用"入口。
   - 每次保存前自动快照，历史里可一键回滚到任意版本。
3. **修复异步回滚**
   - 壁纸选择、预设应用全部改为基于最新状态更新，杜绝旧快照覆盖新改动。
4. **修复 theme 覆盖**
   - 读取时以存储 theme 为准；主题服务偏好仅作为"跟随系统"时的实际解析。
5. **重做壁纸/毛玻璃渲染层**
   - 界面容器改用稳定的 class/data 属性定位；聊天区、侧栏、设置面板全部纳入毛玻璃。
   - 无壁纸时背景氛围（渐变 + 模糊 + 遮罩）仍可见；预览卡真实应用全部效果。
   - 暗色遮罩层级修正：压在所有界面层之上（不挡交互）、跟随圆角。

### 4.5 P1：更全面的参数与 DIY

**配色**（新增）

- 13+ 颜色角色取色器（背景/卡片/浮层/侧栏/文字/边框/强调/成功/警告/错误/链接/代码/选中）。
- 强调色支持"跟随主题包"或"独立自定义"；亮/暗两套配色分别可调。
- 传图生成整套配色：取主色/辅色自动生成主题包（参考 HeiGeAi skin）。

**壁纸**（新增）

- 来源：上传图片（自动压缩 ≤2MB，参考 dsh-dream-skin）/ 粘贴 URL / 内置渐变 / 多图轮换 /
  视频直链（mp4/webm/m3u8）/ WE 壁纸（P2）。
- 显示：cover / contain / 平铺 / 位置 / 随窗口缩放；壁纸自动弱化（参考"自动弱化"）。

**排版与密度**（扩展）

- 字体大小、行高、圆角、卡片间距、页面宽度、密度细分（紧凑/标准/宽松/极宽松）。

**氛围**（新增三组独立滑块，参考 dsh-ui-appearance）

- 面板不透明度、面板毛玻璃强度（侧栏/页面/卡片/弹窗可分区域调）。
- 背景不透明度、背景模糊、背景遮罩；强调色光晕（accent glow）开关与强度。

**动效**（新增）

- 界面过渡时长、减少动态效果开关、滚动条样式。

**高级**（可选，需确认）

- 自定义 CSS 注入（带安全提示，仅本地生效）。

### 4.6 P2：Wallpaper Engine 动态壁纸

**能力**：风格页新增"Wallpaper Engine"入口，扫描本地 WE 目录，以缩略图网格展示壁纸；
点选 Video / Web 壁纸后作为界面动态背景。

**实现要点**：

1. 自动发现：默认读取 `Steam/steamapps/workshop/content/431960/`，支持手动指定目录；
   未安装/未找到时给出引导，不报错。
2. 类型处理：Video 壁纸用视频标签循环播放；Web 壁纸在**沙箱 iframe** 内渲染；
   Scene/Application 从网格中剔除（无法内嵌，与社区插件一致），可降级显示静态预览帧。
3. 性能保护：页面不可见/窗口最小化时暂停播放；可设最大帧率、内存占用提示；
   动态壁纸与"减少动态效果"开关联动。
4. 持久化：只保存壁纸 ID/路径引用，不复制文件；卸载 WE 后自动降级为静态图。

### 4.7 风格页界面改版

- 左侧分类导航：主题包 / 壁纸 / 配色 / 排版 / 氛围 / 对话风格 / 高级。
- 右侧整窗实时预览（不只是小卡片），预览使用真实渲染层。
- 顶部工具条：状态（已保存/未保存/保存失败）+ 保存 / 撤销 / 历史 / 恢复默认（带确认）。
- 主题包卡片网格：内置 + 已保存 + 导入；每张卡片显示预览缩略图与关键信息；一键应用。
- 壁纸选择器：内置 / 本地 / URL / 轮换 / WE（P2）。

### 4.8 安全与性能

- Web 壁纸 iframe 沙箱：禁止脚本访问宿主页面、本地文件与网络凭据。
- 视频/动态壁纸只在需要时播放；内存与帧率上限；低性能模式自动降级。
- 存储大小上限保持；迁移旧 schema 前自动备份。
- 所有写入走现有串行队列 + 原子替换，新增 revision 冲突检测。

### 4.9 组件级高自由度 DIY（预留，后续单独立项）

> 用户建议：希望在现有体系之上，把 DIY 自由度拉到满——不只改整体配色，而是能改到
> **按钮、输入框、卡片等单个组件**的风格，自由搭配成自己喜欢的样子。
> 按用户要求：本建议**先保留、先出方案，不进入当前 M1–M4 执行路径**。

**目标**：

- 风格体系从"整页皮肤"下沉到"组件级样式"，每个常用组件都能独立定制。
- 定制方式以**可视化编辑器**为主（选样式、调参数、即时预览），不要求用户写代码。

**初步方案（后续细化）**：

1. **组件清单**：先覆盖最高频组件——按钮（主/次/危险/幽灵）、输入框、下拉框、
   复选框/开关、卡片、弹窗、标签、列表项、滚动条、消息气泡、分隔线等。
2. **每个组件的可调项**：形状（圆角/描边/填充）、配色（常态/悬停/按下/禁用四态）、
   边框、阴影、字号与字重、图标风格、过渡动效。
3. **组件样式编辑器**：点击页面上的任意组件即可进入编辑（"选中即改"），
   右侧面板实时调参，界面同步预览，所见即所得。
4. **样式配方**：组件级定制可保存为"配方"（如"圆润按钮组"），随主题包一起导入导出、分享；
   内置多套配方供一键套用。
5. **与现有体系的关系**：主题包 = 全局基础 + 组件配方；全局参数优先继承，组件配方按需覆盖。
6. **预留开关位**：后续如需极客级自由，再叠加"自定义 CSS"高级入口（当前不做，仅预留）。
7. **安全与维护**：组件样式用受控参数生成（不放开任意代码），保证不破坏布局；
   自定义 CSS 若开放则仅本地生效、带风险提示。
