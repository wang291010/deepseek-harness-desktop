## 0. 计划定位与执行原则

### 总目标

把 DeepSeek Harness Desktop（B 端）持续打磨成个人 AI 工作台：六页能力（Agent /
知识库 / 专家 / 风格 / 监控 / 工作流）全部可用、任务中心与 AI 协作成为日常核心，
同时保持"稳定可发布、可回滚、可自动更新"的桌面发行基线。

### 执行原则

1. 板块化推进，一次只动一个板块；每个板块按固定循环：现状核验 → 方案（含决策点）→
   备份 → 实施 → 回归验收 → 更新文档 → 提交。
2. 验收通过才算完成；未验收的功能一律标记为"已开发，待回归"，不算正式完成。
3. 任何改动先备份；Client 改动刷新即生效，Host 路由/命令与专家 preset 改动需重启
   B 端；B 端故障不影响 A 端；A/B 不同时打开同一会话。
4. 安全约束持续生效：文件接口仅本机回环、发布前敏感审计、profile JSON 无 BOM、
   旧 DSH 数据不迁移不删除（除非决策清单明确）。
5. 每阶段结束时可发布一个版本；版本发布走既定 SOP（见 Phase 7）。

#### 1A.2 市场对标（本次任务面板的设计参照）

- **Linear**：键盘优先、Cmd-K 全局入口、极快响应、最小化；适合个人工作台的轻量感。
- **Todoist Quick Add**：任意位置一键建任务、自然语言解析项目/优先级/日期；适合"在 AI 协作页直接发任务"。
- **GitHub Actions / CI 运行视图**：一次运行 = 阶段步骤列表，每步 running / completed / failed 徽标 + 日志 + 耗时；是"AI 团队执行进度"最直观的参照。
- **LangChain DeepAgents / agent-teams-dashboard**：实时展示子代理流、每个子代理独立进度卡、可展开对话与工具调用统计；适合本工作台的逐代理进度卡。
- **Claude Code Agent Monitor**：Kanban 状态板 + 会话/代理/工具实时活动 + 事件驱动更新（对比当前 1.8s 轮询，后续可升级 SSE/WebSocket）。
- 结论：任务面板以"线性列表 + 运行视图 + 快速创建"为核心，不堆企业级字段；AI 协作采用 CI 式运行页，规划阶段用不确定进度条，执行阶段用逐代理状态卡。

#### 1A.3 状态机与进度可视化设计

规划阶段：

- Host 在 `orchestration_plan` 开始时先把记录置为 `planning` 并落盘，生成完成后再写 `planned` + 方案版本；请求立即返回，生成在后台队列执行，客户端轮询刷新。
- 规划中 UI：不确定进度条 + 文案（"AI 正在生成第一份方案…"/"正在按反馈重新编排 V2…"）+ 已用时长；方案版本区显示"V1 生成中"。
- 崩溃/重启恢复：`recoverInterruptedOrchestrations` 把卡在 `planning` 的记录标记为失败并允许重新生成（该函数已存在，落地 `planning` 后即可生效）。

执行阶段：

- 顶部整体进度条：`已完成子代理 / 子代理总数`，主代理运行后进入"主代理汇总中"。
- 逐代理状态卡：planned / waiting / running / completed / failed / cancelled 徽标；运行中的代理显示已用时长；完成代理显示交接摘要（可展开）。
- 阶段步骤条：想法 → 方案 → 执行 → 验收，高亮当前阶段。
- 执行时间线：开始、每批子代理完成、主代理汇总、进入验收；失败与取消带原因。
- 数据已具备：Host 已在每个 worker/main 的状态、`startedAt`/`completedAt`、`output`/`error` 落盘；客户端只需按上述 UI 消费。

#### 1A.4 重构实施清单（小步、每步可验收）

1. 错误与网络层：fetch 统一包装（超时、空响应容错、错误信息可读）；错误表面可复制、可关闭、不挡交互；所有失败路径复位 `busy`。
2. 快速创建：AI 协作页顶部 Quick-Add（直接 `orchestration_create`），创建后选中并保持项目范围。
3. 转交修复：想法库 → AI 协作跳转自动修正范围并选中新任务；空态文案区分原因。
4. 规划异步化 + `planning` 落盘 + 规划进度条（首次生成与重新生成都覆盖）。
5. 执行进度可视化：整体进度条、逐代理状态卡、阶段步骤条、执行时间线。
6. 反馈草稿与已提交反馈分离；提交后清空；历史 tab 展示修改依据。
7. 项目创建增加"浏览…"选文件夹；路径输入保留。
8. 运行中交互回归：项目切换、会话操作、任务中心开关、tab 切换全部可用；修复确认的根因。
9. 双客户端同会话风险提示（沿用 P1 待办，一并收口）。
10. 中断/异常任务的“继续执行”：保留已完成代理的产出，只重跑未完成代理后由主代理汇总；
    失败原因可复制诊断；无法解决再回退“重新生成方案”（2026-08-18 追加）。

#### 1A.5 验收标准

- 上述 7 个用户反馈场景逐一复测通过（含真实执行一轮小任务）。
- 规划中与执行中均有明确进度反馈；无空白无进度时段。
- 任何错误都可一键复制；错误提示不阻塞其他操作。
- 运行期间项目切换等全局操作不受影响。
- 关闭重开任务中心后，反馈框为空白（未提交草稿不残留）。
- 项目可直接选文件夹创建。

### Phase 2.5：多AI协作工作台（主会话驱动）（P2.5）

> 需求来源：用户与其他 AI 讨论后提出的改造方案（2026-08-19），目标是让"任务中心-想法库-
> AI 协助"演进为**主会话驱动的多AI协作工作台**：像聊天一样持续对话、复杂任务自动拆解给
> 多个专业子代理、状态实时可视化、上下文可跨会话恢复。

#### 现状核对（与方案的重叠部分，已有能力）

方案中的"多AI协作引擎"在 P1A 已实现大半，无需重复建设：

- 任务拆解与编排：`orchestration_create / set_planning / plan / set_plan / start / accept /
  request_changes / cancel / remove`；主协调代理 + 至多 6 个子代理、`dependsOn` 依赖、
  `maxParallel`（1–4）并行上限、plan 版本与 runs 历史、`thread` 对话记录。
- 执行与监控：逐代理状态卡（planned/waiting/running/completed/failed/cancelled）、
  阶段步骤条、整体进度、主代理汇总、运行中可终止、验收后可"继续与主代理对话"（918d32c）。
- 中断恢复：`recoverInterruptedOrchestrations` 保留已完成代理产出只重跑未完成代理；
  模型选择与白名单（V4 Flash / V4 Pro）、不可用回退。

#### 真正的新增工作（方案增量）

按模块拆分：

- A 会话窗口改造：统一会话入口（想法库改为会话内快捷引用抽屉）、普通/多AI 模式切换开关、
  子任务折叠卡片内嵌消息流、@引用与拖拽上传、快捷命令（`/new` `/plan` `/memory`）。
- B 协作引擎增强：复杂度自动判断（启发式规则 + LLM JSON，阈值可配）、子代理池配置化
  （角色/能力标签/模型/系统提示词 + 匹配）、看门狗（单任务超时默认 300s、重试 ≤2 次、
  换同类代理、全失败标记"需人工介入"）。

  持久化存储，Token 恢复跨会话上下文。

### Phase 3：监控页（P4）

五板块：

1. 账户总览：余额、累计费用、预计可用天数、费用趋势、是否峰值计价时段。
2. 用量统计：输入/缓存读/缓存写/输出 Token；按模型、按天；请求数；对话轮次；
   峰谷费用拆分。
3. 会话洞察：消耗最高会话、活跃会话、活跃天数、会话轨迹、时间线。
4. 实时面板：当前会话实时 Token/费用、运行状态、模型、专家。
5. 告警：余额/日预算/月预算阈值；页面内横幅 + 导航栏红点；不依赖系统通知。

数据源：`dsh-usage-stats`、原生 trajectory、Session 数据、本地费用配置。

验收标准：五板块可用；数据与本地统计源一致；峰谷计算正确；阈值触发页面内提醒。

### Phase 4：工作流页（P5）

验收标准：模板一键运行；状态与失败原因可见；模板可编辑；定时任务按计划触发。

### Phase 5：知识库与蒸馏（P6）

先决策（决策点 D4/D5），再开发。

建议方案：

- 形态：本地 Markdown Vault（目录结构与 Obsidian 兼容，但不强制安装 Obsidian）。
- 位置：默认 `DSH_HOME` 下 `knowledge/`，可在设置中改。
- 功能：知识库浏览页、Markdown 管理、标签、项目分类、MOC 索引、搜索检索。
- 蒸馏：Agent 工具栏"蒸馏" → 读取当前会话 → AI 提炼（结论/方法/决策/待办/背景）→
  生成 Markdown → 人工确认/编辑 → 写入 Vault → 更新标签与索引。
- 检索：MVP 手动触发注入（"检索相关知识"），后续再评估自动注入；不同专家可按目录
  范围限制知识。
- 防垃圾：仅经人工确认的文档入库；重复/冲突知识走"新文档 + 关联链接"并提示。

验收标准：浏览/管理/检索可用；蒸馏全流程走通；新会话可检索到已入库知识。
